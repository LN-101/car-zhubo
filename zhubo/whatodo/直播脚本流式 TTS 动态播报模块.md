## 2. 模块硬性要求

原文位置：4.3「直播脚本流式 TTS 动态播报模块」（正文第 27–31 段）。

| 编号 | 要求 | 原文规定的行为或指标 |
| --- | --- | --- |
| TTS-01 | 双渠道脚本录入 | 支持本地脚本文件上传，以及前端文本框手动输入直播话术。 |
| TTS-02 | 流式音频生成播放 | 无需全文生成完毕，即可边生成音频边实时播放。 |
| TTS-03 | 动态改稿 | 音频未播放完成时，支持随时增加、删除、修改脚本内容；修改后实时刷新流式音频输出。 |
| TTS-04 | 播报参数调节 | 支持语速、音量、语调自定义调节。 |
| TTS-05 | 首音延迟 | TTS 流式从文本输入到语音开始输出的延迟 ≤ 3 秒。 |
| TTS-06 | 连续播放与测试 | 保证流畅播放，并提供延迟测试报告。 |

原文 4.3 同时要求所有功能可现场演示。

## 3. 与 TTS 关联的其他模块要求

这些要求来自相邻模块，列出用于明确联动关系；不表示本 TTS 模块需独立实现整个语音克隆或 RAG 系统。

### 3.1 拟人化语音克隆联动

原文位置：4.3「拟人化语音克隆模块」（第 32–35 段）。

- 支持上传少量真人语音样本完成主播音色克隆，复刻真人语气、停顿、情绪节奏。
- 内置多套预制汽车主播音色，如沉稳、活力、亲民等，支持一键切换。
- 克隆音色与流式播报打通，实现全程拟人化直播讲解，降低机械播报感。
- 提供音色拟人度主观评测报告。

### 3.2 智能问答语音输出联动

原文位置：4.3「基础汽车直播智能交互配套能力」（第 36–38 段）。

- 上游支持绑定车系、车型筛选，接受车型参数、优惠、配置对比等咨询。
- 依托 RAG 知识库和大模型完成专业问答，回复需同时提供文字与 TTS 语音输出。

## 6. 原文尚未规定的实现细节

以下属于后续实现需确定的口径，不是新增硬性要求：

- 脚本上传的文件格式、大小限制与文本编码。RAG 模块规定的 PDF/Word/TXT 格式不能直接视为脚本上传格式要求。
- 动态改稿对当前正在播放片段的处理方式：立即中断替换，还是播放至边界后使用新稿；已播内容被修改时是否重播。
- 语速、音量、语调的范围，以及参数调整是否立即作用于当前播报。
- 延迟测试的硬件、样本、冷启动或预热状态、统计口径；原文只给出 ≤ 3 秒阈值。
- 改稿响应灵敏度与流畅播放的数值阈值；原文未给出。
- 真人样本的数量与时长、预制音色的具体数量、主观评测方法；原文未给出。

## 7. 建议验收观察点

以下由上述原文整理，便于后续测试，不额外设定原文之外的指标：

1. 分别通过文件上传和文本框提交脚本，两种方式均可触发播报。
2. 使用长脚本验证：全文音频生成结束前已开始播放。
3. 播放尚未结束时分别增加、删除、修改脚本，观察后续音频是否按新稿刷新。
4. 分别调整语速、音量、语调，检查输出是否有相应变化。
5. 记录文本输入至语音开始输出的时间，核对 ≤ 3 秒要求；同时记录播放连续性并生成测试报告。
6. 联动验收时，验证克隆音色和预制音色可用于流式播报，问答回复同时具有文字和语音输出。
7. 核对动态改稿方案、量化测试数据、部署说明和演示材料是否齐全。
